# Prompt 030A — Computer Architecture Three-Part Grading and Assignment Consolidation

Date: 2026-08-24
Owner: Jeremy Evert
Applies to: Prompt 030 Computer Architecture → Optional Computing Commons end-first migration

## Authority

This prompt is a binding owner amendment to Prompt 030.

Where Prompt 030 or the current Architecture grading/source model conflicts with this amendment, **030A wins**.

The migration outcome is no longer merely “remove shared enrichment.” The live and source course should also be simplified toward roughly **17 meaningful gradebook objects**, without inventing filler and without harming existing student work.

## Final course grading doctrine

Computer Architecture has exactly three required graded components:

| Component | Weight |
|---|---:|
| Weekly Canvas Engagement | 15% |
| Architecture Reasoning Odyssey | 75% |
| End-of-semester Architecture Reflection | 10% |
| **Total** | **100%** |

No other required graded category remains.

### 1. Weekly Canvas Engagement — 15%

Jeremy will check each Monday whether each student has been active in Canvas during the preceding week.

This is **not** a student assignment and should not create a new submission burden.

Preferred Canvas shape:

- one instructor-entered gradebook object/column for the semester;
- no student submission required;
- no weekly reflection, receipt, quiz, or check-in form;
- no due-date treadmill;
- Jeremy updates the same grade column cumulatively as weekly checks occur;
- if implemented as points, prefer a simple cumulative structure such as one point per weekly engagement check, with the assignment group weighted 15%.

Do **not** create 15 separate Canvas assignments merely to record the weekly access checks. The owner goal is fewer objects, not a different flavor of clutter.

If Canvas/tooling makes a single cumulative instructor-entered column impractical, choose the smallest object count that preserves the same doctrine and document why.

### 2. Architecture Reasoning Odyssey — 75%

All substantive graded technical work belongs in one **Architecture Reasoning Odyssey** category worth 75% of the course.

The course should have roughly one meaningful Reasoning Odyssey assignment per substantive Architecture week, not separate assignment objects for every micro-step, prelude, receipt, explanation, investigation, and duplicated evidence wrapper.

A Reasoning Odyssey assignment must assess actual Computer Architecture principles, such as:

- representation and machine-visible state;
- ISA / RISC-V concepts;
- CPU organization and datapath/control;
- performance and measurement;
- memory hierarchy and locality;
- caches;
- pipelining / hazards where in scope;
- binaries, assembly, traces, profiling, or machine behavior;
- hardware/software interaction;
- architecture design tradeoffs;
- other clearly Architecture-native outcomes already present in the course source.

Use the strongest existing Architecture material. Consolidate where necessary.

For example, if the old design created separate “Weekly Architecture Investigation” and “Explain / Defend” assignments for the same week, and neither has student activity, prefer **one weekly Reasoning Odyssey assignment** that includes the investigation plus the explanation/defense evidence needed to prove understanding.

Likewise, Machine Dossier/checkpoint ideas may remain as deeper expectations or milestone-shaped Reasoning Odyssey assignments, but they do not need a separate grading category if the same Architecture learning can live coherently inside the 75% Reasoning Odyssey group.

### Assignment-count target

The target is **approximately 17 meaningful gradebook objects**, not a magic exact number.

A clean target shape is:

- 1 cumulative Canvas Engagement object;
- roughly 15 Architecture Reasoning Odyssey assignments, one per substantive Architecture week when real Architecture work exists;
- 1 end-of-semester Architecture Reflection.

Do not invent an assignment solely to hit 17. If the strongest pure Architecture course naturally lands at 15, 16, 17, or 18 objects, prefer the academically cleaner result.

### Reasoning Odyssey weight distribution

The Reasoning Odyssey assignment group is weighted **75%** as a group.

Prefer simple, comprehensible assignment point values inside the group. Equal points are acceptable when assignments are genuinely comparable; larger milestone weeks may carry proportionally more points when the evidence burden is materially larger.

Do not create dozens of fractional assignment-group percentages. Let the group carry the 75% weight and let assignment points express relative size inside it.

### 3. End-of-semester Architecture Reflection — 10%

Keep one final Architecture reflection worth 10%.

It should use the student’s Architecture evidence trail to explain what they can now understand, inspect, measure, or defend that they could not at the beginning of the term.

Do not require a separate shared Professional Minds, career, AI Fluency, Farkle/ML, or generic end-of-semester reflection for course credit.

## What leaves the required Architecture grade

The following are not required graded Architecture categories under this doctrine:

- Semester Kickoff / Success Foundations;
- AI Fluency / Monday Moments;
- Professional Minds Wednesday/Friday;
- Professional Pathway / resume / career artifacts;
- Farkle + Machine Learning shared finale;
- generic containers / WSL / LaTeX / Git / Linux training when they are merely accelerators;
- separate Weekly Explain / Defend category;
- separate Machine Dossier grading category;
- separate course-evaluation points;
- any duplicate receipt/reflection/checkpoint object whose evidence can live inside the weekly Reasoning Odyssey assignment.

Useful shared material is harvested into optional Computing Commons under Prompt 030.

Useful Architecture-specific expectations are consolidated into the weekly Reasoning Odyssey assignments rather than discarded.

## Existing student activity protection

Existing student submissions, scores, or grades are still protected by Prompt 030.

If an old Architecture assignment has student activity:

- preserve the object and earned history;
- do not delete or rewrite earned evidence merely to achieve the target object count;
- classify it as historical/legacy/bonus as appropriate in the migration ledger;
- let the final live object count temporarily exceed the clean target if that is what student protection requires.

The clean ~17-object target governs the **future required course design**, not permission to erase history.

## Zero-activity Architecture-core consolidation authority

Prompt 030 previously protected every Architecture-core object from deletion merely because it was “core.” This amendment narrows that rule.

A zero-activity Architecture-core object **may be consolidated and removed** when all are true:

1. its Architecture learning outcome/evidence is preserved in another surviving Reasoning Odyssey assignment or final reflection;
2. the surviving assignment is verified in source and Canvas before deletion;
3. submission count = 0 and recorded grade/score count = 0;
4. no student attempt/comment/rubric evidence would be destroyed;
5. module/navigation references are repaired;
6. the consolidation makes the course simpler without reducing the Architecture learning target.

This is how the course moves from 116 assignment objects toward roughly 17 without throwing away the actual Architecture education.

Do **not** copy Architecture-core material into Computing Commons merely to delete it. Commons is for shared/enrichment/accelerator material. Architecture-core content stays in Architecture, consolidated into fewer stronger assignments.

## Live grading-weight migration

The final source model must record the 15 / 75 / 10 doctrine.

For live production Canvas, perform weighting changes only after a before/after impact preview demonstrates that existing earned student credit is preserved or improved.

If live weights cannot be safely normalized in the same campaign without affecting existing earned work:

- finish the safe content/object cleanup;
- preserve the existing activity-bearing legacy objects;
- record the exact remaining weight-normalization step in the durable report;
- do not hold the rest of the chain-gun cleanup hostage to unsafe grade math.

## Completion test added to Prompt 030

Before declaring the Architecture campaign complete, verify:

- active source doctrine is 15% Canvas Engagement / 75% Architecture Reasoning Odyssey / 10% Final Reflection;
- there is no required shared-enrichment grading category left in the future source model;
- the future required assignment inventory is approximately 17 meaningful objects, or the report explains a small academically justified difference;
- shared/enrichment material removed from Architecture has a verified optional Commons home when worth preserving;
- zero-activity duplicate Architecture-core objects were consolidated where safe;
- all existing student activity and grades remain intact;
- no weekly student paperwork was created for Canvas Engagement.
