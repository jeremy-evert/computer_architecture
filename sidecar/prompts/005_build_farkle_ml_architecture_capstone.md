# Sidecar Prompt 005 - Build the shared Farkle + Machine Learning Week 16 experience

**Status:** OPEN - filename retained for history; the former Architecture-capstone framing is superseded.  
**Owner:** Foreman  
**Mode:** inspect existing Farkle assets -> prototype small shared experience -> validate -> report

## Mission

Build **Week 16 Farkle + Machine Learning** as the shared applied/fun week used across the computing-course family.

Computer Architecture has already reached its technical finale in Week 14.

Week 16 may let students notice architecture naturally, but it must **not** become:

- Checkpoint 4;
- a hidden Architecture capstone;
- a new Machine Dossier layer;
- a heavy profiling project;
- a new ML theory unit.

The desired student feeling is:

> I can play with a real computational workload and notice things about the machine because I now know how to look.

## Pinned constraints

1. Week 14 already froze the Machine Dossier.
2. Week 15 is asynchronous wind-down/catch-up.
3. Week 16 is joyful shared application.
4. Week 17 is reflection.
5. CPU-only required path.
6. GPU/accelerator path optional.
7. No paid AI/CLI requirement.
8. No large model/dataset download.
9. No prior ML expertise required.
10. Architecture-specific evidence must remain **light**.

## Desired Architecture flavor

A bounded optional/light prompt may ask:

- What did you predict this workload would care about?
- Did latency, throughput, vectorization, data movement, or another familiar idea appear?
- What surprised you?
- Which existing dossier/lab experience helps explain that surprise?

Do not require a new multi-layer Architecture investigation.

## Tooling

Choose the smallest open/free Farkle + ML path shared with sibling courses.

Prefer:

- deterministic seeds;
- bounded runtime;
- small dependencies;
- understandable output;
- easy CPU completion;
- optional GPU path only when it fails gracefully.

## Instructor recording opportunity

Week 16 can include a fun Stack Showcase where Jeremy runs the shared workload through parts of his real stack, including local/frontier AI tools or different hardware.

That showcase is enrichment, not a specification students must reproduce.
