# Prompt 004_f - Author Week 9: Follow the Program Down

**Status:** OPEN  
**Depends on:** 004_b through 004_e  
**Checkpoint:** Machine Dossier Checkpoint 2  
**Calendar:** shortened by Fall Break; no normal Friday burden

## Why this week exists

Weeks 5-8 have shown pieces of the machine. Week 9 proves whether students can connect them without hand-waving.

This is an integration week, not an excuse to add another chapter.

## Central question

> **Can I follow one small program through the stack without losing the evidence chain?**

## Continuity requirement

Reuse the persistent Weeks 6-8 specimen unless there is a documented reason not to.

The chain should feel familiar enough that the intellectual work is integration rather than deciphering a new program.

## Required synthesis chain

A defensible path should connect several of:

- source meaning;
- values/representation;
- compiler output;
- RISC-V instructions/encoding;
- registers/memory state;
- bounded datapath/control interpretation;
- dependency/performance implications;
- resulting output.

Not every student needs to explain every compiler phase. This is Computer Architecture, not a compiler course.

## Monday package

Frame integration as an evidence problem:

> Where does each claim about this program come from, and what tool/representation lets us verify it?

Use a map of layers, then walk enough of the persistent specimen to prepare the checkpoint without giving away the student's whole chain.

## Wednesday investigation / Checkpoint 2

Checkpoint 2 should require a coherent source-to-machine narrative with actual artifacts from the stable lab.

Likely evidence:

- source excerpt;
- representation/value claim;
- disassembly;
- architectural state/trace;
- datapath interpretation;
- performance/dependency observation where useful;
- explicit links between evidence items.

The checkpoint should be larger than Week 6 because integration is the goal, not because there are more worksheets.
