# COMSC 3013 Fall 2026 - asynchronous M/W/F production map

**This is the master target list for the course production pipeline.**

COMSC-3013-1438 is officially online/asynchronous. The Monday / Wednesday / Friday rhythm below is a **release, recording, and authoring chassis**, not an attendance schedule.

The course intentionally borrows the recognizable family rhythm from CS1/CS2/DSCT while replacing face-to-face pair programming/show-and-tell with an online laboratory and instructor recording model.

## Three weekly production modes

### Monday - Think / Frame / Lecture

- AI Fluency lens;
- central machine question;
- course-owned digest/LaTeX source;
- Beamer/slide deck;
- instructor-recorded lecture/workthrough;
- prediction before students see the experiment.

Jeremy may visibly use ChatGPT, Claude, Copilot, Gemini, Grok, Codex, Claude Code, aider, OpenClaw, local models, and other real tools while recording. The point is to model fluent investigation and verification, not prescribe a vendor.

### Wednesday - Investigate / Break / Measure

- Professional Minds Wednesday topic;
- hands-on sensory lab / trace / build / measurement;
- reproducible course environment;
- machine-readable evidence where possible;
- instructor canonical lab walkthrough may be screen-recorded with the real stack.

### Friday - Explain / Defend / Stack Showcase

- Professional Minds Friday topic;
- bounded student evidence receipt;
- plot/table/trace/explanation;
- instructor **Stack Showcase**: a real machine, cluster, profiler, compiler, GPU, NRP path, agent workflow, or other authentic system showing where the week's road leads.

The instructor stack is visible pedagogy, not a required student stack.

## Technical production package for each authored Week 5-14

Future authoring should gradually make each technical week contain:

1. **Lecture source**
   - concise course-owned explanation;
   - LaTeX/Markdown digest;
   - slide/Beamer deck;
   - instructor recording plan;
   - worked example/prediction.
2. **Investigation lab**
   - supported environment;
   - sensory perturbation when appropriate;
   - exact run path;
   - machine-readable data where practical;
   - fallback data/trace when personal hardware cannot expose the phenomenon.
3. **Visualization**
   - course-provided Python/matplotlib helper;
   - a plot/table only when it clarifies the mechanism;
   - no grading on decorative plotting tricks.
4. **Evidence receipt**
   - claim;
   - relevant measurement/trace;
   - explanation;
   - revision/correction when evidence conflicts.
5. **Friday Stack Showcase plan**
   - one authentic professor-owned system/tool/workflow that shows where the idea leads;
   - no requirement that students own the demonstrated tool/hardware.
6. **Reference map**
   - open/free required path;
   - primary/official sources where needed;
   - commercial sources instructor-only/optional.
7. **Validation receipt**
   - lab actually executed in the supported path;
   - commands/links checked.

## Sister-week continuity rule

- Weeks 5-6 reuse the same machine/values/tiny program from component choice into representation/ISA.
- Weeks 7-8 reuse the same instruction/program from correct execution into pipeline timing.
- Week 9 reuses material from Weeks 5-8 for integration.
- Weeks 10-11 reuse one program/data-access story from memory-hierarchy behavior into VM/OS abstraction.
- Weeks 12-13 reuse a workload/data layout from multicore scaling into specialized execution.
- Week 14 returns explicitly to the Week 5 machine.

## Production principle

**Monday gives the student a model. Wednesday makes the machine argue with the model. Friday forces a better explanation.**

That is the asynchronous substitute for the live energy of pair programming and show-and-tell.
